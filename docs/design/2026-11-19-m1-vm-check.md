# M1 check on the development VM — 2026-11-19

What was checked: the built `memctl` binary (linux/arm64, from commit after
stage plan 0001 T17) on a small notes root shaped like path-linked Basic
Memory notes, driven over stdio by a script that speaks MCP, plus
`memctl check` on the same root. The live check with Claude Code on a copy of
a real notes root (SPEC-0004, "Live check") is not part of this record: the
VM has no Claude Code, and it is left to the maintainer.

The root: `hosts/intpxy.md` (type host, an observation, a relation to a note
that does not exist), `services/intpxy.md` (same title, a path link to the
host), `runbooks/Renew certificates.md` (a relation to the service), in a git
repository.

## Findings

- The server lists the four read tools `context`, `list`, `note_read`,
  `search`.
- `search` for `proxy 10.11.0.51` finds both notes that hold those words.
- `note_read` with the shared title `intpxy` returns `ambiguous` with both
  paths, as design D23 requires; a path ref resolves.
- `context` from `hosts/intpxy` at depth 2 finds the service (backlink) and
  the runbook (two hops).
- `list` with type `host` lists the host note only.
- A line appended to the host note in place of an editor is found by the next
  `search`, without a restart (design D15).
- `memctl check` reports the one dangling path link as a warning, `3 notes
  checked, 0 errors, 1 warning.`, and exits 0.

Benchmarks at 5,000 notes are recorded in stage plan 0001 ("Verification
notes"); the first `context` call after a change misses its 20 ms target
(about 80 ms), a finding for the design's scale risk that is settled there.

Nothing found here changes a spec or an ADR.
